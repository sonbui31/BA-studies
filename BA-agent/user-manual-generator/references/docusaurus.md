# Docusaurus 3.10 Publishing Guide

Use Docusaurus when the deliverable should be a browsable, versionable user manual with search, sidebars, clean routes, and GitHub Pages deployment.

## Version And Compatibility

- Target Docusaurus `^3.10.0`.
- Keep a lockfile and upgrade dependencies deliberately.
- Docusaurus 3.10 is the final v3 line and helps prepare for Docusaurus v4.
- Prefer `future: { faster: true }` for new sites when `@docusaurus/faster` is installed.
- Use `storage: { type: 'localStorage', namespace: true }` when the site can share a domain with other Docusaurus apps.
- Write Markdown in Docusaurus v3 syntax, especially admonitions with bracketed titles.

## Recommended Structure

```text
manual/
|-- package.json
|-- package-lock.json
|-- docusaurus.config.js
|-- sidebars.js
|-- README.md
|-- static/
|   |-- .nojekyll
|   `-- img/
|       |-- logo.png
|       `-- screenshots/
|-- src/
|   |-- css/
|   |   `-- custom.css
|   `-- pages/

```

## Home Page Template

Always create `src/pages/index.js` as a product introduction page, not a duplicate of the docs intro page and not a redirect. The brand/logo click should land here. A strong default pattern is: left-aligned product story, primary docs CTA, secondary feature CTA, real product screenshot on the right, and a compact summary band beneath the hero. Adapt the layout to the product domain instead of forcing every manual into the same composition.

```js
import React from 'react';
import Layout from '@theme/Layout';
import Link from '@docusaurus/Link';
import useBaseUrl from '@docusaurus/useBaseUrl';
import styles from './index.module.css';

const summary = [
  { title: '{{DOMAIN_1}}', text: '{{DOMAIN_1_DESCRIPTION}}' },
  { title: '{{DOMAIN_2}}', text: '{{DOMAIN_2_DESCRIPTION}}' },
  { title: '{{DOMAIN_3}}', text: '{{DOMAIN_3_DESCRIPTION}}' },
];

export default function Home() {
  const heroImage = useBaseUrl('/img/screenshots/{{HERO_SCREENSHOT}}');

  return (
    <Layout title="{{SYSTEM_NAME}} | {{PRODUCT_CATEGORY}}" description="{{ONE_SENTENCE_VALUE_PROP}}">
      <main className={styles.home}>
        <section className={styles.hero}>
          <div className={styles.heroCopy}>
            <p className={styles.kicker}>{{PRODUCT_CATEGORY}}</p>
            <h1>{{SYSTEM_NAME}} {{MAIN_PROMISE}}</h1>
            <p className={styles.heroText}>{{ONE_SENTENCE_VALUE_PROP}}</p>
            <div className={styles.actions}>
              <Link className={styles.primaryButton} to="/docs/intro">
                Xem hướng dẫn
              </Link>
              <Link className={styles.secondaryButton} to="{{PRIMARY_MODULE_ROUTE}}">
                {{PRIMARY_MODULE_LABEL}}
              </Link>
            </div>
          </div>
          <div className={styles.heroMedia}>
            <img src={heroImage} alt="Màn hình tổng quan của {{SYSTEM_NAME}}" />
          </div>
        </section>
        <section className={styles.summary}>
          {summary.map((item) => (
            <div key={item.title}>
              <strong>{item.title}</strong>
              <span>{item.text}</span>
            </div>
          ))}
        </section>
      </main>
    </Layout>
  );
}
```

## Markdown Rules

Use root-absolute Docusaurus paths for docs and static assets:

```markdown
[Đăng nhập](/docs/getting-started/login)
![Màn hình đăng nhập](/img/screenshots/login/login-01-overview.png)
```

Use Docusaurus v3 admonitions:

```markdown
:::tip[Mẹo]

Hãy lưu công việc trước khi cập nhật.

:::

:::warning[Lưu ý]

Thao tác này chỉ dành cho người có quyền phù hợp.

:::
```

Do not use the older title form `:::tip Mẹo`; it can render as plain text instead of a highlighted admonition.

## GitHub Pages Workflow

Use the official Pages artifact flow when the repo deploys from GitHub Actions.

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: build

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    needs: build
    runs-on: ubuntu-latest
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

## Deployment Checks

- Run `npm run build`.
- Run `npm run serve` and open the local URL when possible.
- Confirm project pages use `https://<owner>.github.io/<repo>/...`.
- Confirm root pages use `https://<owner>.github.io/...`.
- Test a cache-busted public URL after deploy: `?v=<commit-sha>`.
- On GitHub Pages project sites, test the repo-prefixed path, for example `https://<owner>.github.io/<repo>/docs/intro`. A root path such as `https://<owner>.github.io/docs/intro` is only correct for root Pages repos.
- Run `node user-manual-generator/scripts/audit-docs.js <manual-dir>` before delivery.
- To add project-specific banned terms without editing the shared skill, run `DOCS_BANNED_TERMS="Term A,Term B" node user-manual-generator/scripts/audit-docs.js <manual-dir>`.
